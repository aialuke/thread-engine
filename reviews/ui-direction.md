# UI direction: decision log

A running record of decisions about a Thread Engine interface: what was decided, why, and what was rejected. Each round of the mock builds on this. Nothing here is built yet.

Mock: https://claude.ai/artifact/8zaBcxWAknJaXWkReQQPqg (private until the operator shares it).

## Build notes (not decisions; needed before the real thing)

- **Facts found in the 25 Sep build-strategy session (for the research layers):**
  - **A headless prompt can approve.** Tested on a throwaway copy in a scratch folder, never a real draft: `claude -p` (Claude Code 2.1.282) and `grok -p` (Grok Build 1.0.40) both fire the project's `UserPromptSubmit` hook for the prompt and honour its block. So from this repo, `claude -p "/approve <slug>"` or `grok -p "/approve <slug>"` approves a draft. The guard stops an agent doing this from a shell; nothing stops any other program on the Mac, and any program can also write `APPROVED` directly. Anything that runs commands must never pass a prompt starting `/approve`, and the Approve design (Q8) can't rely on `approve.py` alone.
  - **Both CLIs enforce the project's hooks headlessly** (`PreToolUse` deny blocks) and stream each tool call (`--output-format stream-json` / `streaming-json`). Grok's hooks fail open on a crash or timeout; only an explicit deny blocks, which is what `guard_approved.py` sends.
  - **Subscription terms:** headless Claude Code runs draw on the user's own Claude subscription. Anthropic's terms allow the unmodified CLI with the user's own login, and don't allow an app that offers claude.ai login on the user's behalf. Check every engine's terms in layer 3.
  - **Remote Control:** Claude Code's Remote Control sends prompts from the iPhone app to a Mac session with local hooks and files. The docs don't say whether `UserPromptSubmit` fires for those prompts (untested).
  - **Grok ran a skill on its own.** In the same scratch test, a plain prompt ("Reply with the word ok.") led Grok to invoke the test skill unasked. `/draft-thread` and `/verify-settings` don't set `disable-model-invocation` (`reviews/ui-build-handoff/system-today.md` §2), so a model can start them itself today.
