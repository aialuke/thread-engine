## Key Question 1: Candidate sourcing. How does an original from a ~36-follower account get into For You and Following?

### Takeaway
A follower sees the post through Thunder, the in-network store of recent posts from everyone the viewer follows; no engagement is needed. For a stranger (out-of-network), the main Phoenix retrieval corpus is the `1fav_1day` index, so the post generally needs **at least one like** first. A small-author "tail" index and a post-creation index exist and are filled without a like, but the code does not show that Home For You actually queries them. Once any source retrieves the post, a default cold-start rule can lift one original per request from an author with 1,000 followers or fewer to about the 16th slot. The Following tab is plain reverse-chronological search with no ranking.

### Inferences
- INFERENCE: For a 36-follower account, most out-of-network reach has to come through Phoenix retrieval over `1fav_1day`, so **the first like is the gate into the main stranger pool**. Because posts are re-indexed at 1, 2, 4, 8 … likes and the like-index windows are 24-48 h, early likes matter more than late ones.
- INFERENCE: The tail and post-creation indexes suggest X is building a no-like path for small authors. Whether Home For You queries them is not shown, and `PhoenixColdStartMaxResults` = 0 plus MoE off suggests cold slots are not reserved by default. Do not plan around the tail index.
- INFERENCE: The cold-start lift helps only a post that some source has already retrieved and that already ranks inside the top 85% of that viewer's candidates. It is a lift, not a retrieval path. For an out-of-network viewer, the lifted score is then multiplied by 0.75 (Key Question 3), so the post can land below slot 16.
- INFERENCE: Followers get the post regardless of likes, because Thunder pulls every followed author's recent originals. With 36 followers, that audience is 36 people at most, and they see it only if it outranks their other candidates in For You. In Following it appears chronologically.

### Gaps
- Whether the production Phoenix retrieval launch config includes `TAIL` or `post_creation` for Home, and the live `cold_start_max_age_seconds` and dataset capacities: deployment config, not in the repo.
- Thunder's live `post_retention_seconds`.
- What the `lifecycle = Development` label on the like and post-creation forwarders means in practice. The processors they feed are labelled `Production`, so the label can't settle which paths are live.
- How `author_followers_count` is hydrated for home-mixer candidates (from a Gizmoduck hydrator per the pipeline; I did not trace the exact field).

## Key Question 2: Premium, verified or "blue" signals. Author-side boosts, viewer-side differences, verified-only features, reply ranking

### Takeaway
At this commit, **For You and Following ranking contains no Premium or verified term.** The value model's inputs, the VM ranker request and the default Phoenix ranker features have no verified or subscription field. The viewer's subscription level is read only for stats and ads logging. Verified status does enter the code in four other places: (1) a credibility PageRank job (`user-cred-v2`) that seeds trust mass from Premium and verified accounts, whose score exempts "high PageRank" accounts from several spam rules; (2) text-embedding inputs, where the v8.2 renderer writes "Verified: Blue (tier)" into the post's embedding prompt; (3) visibility rules, where "verified-only replies" limits replying but not seeing; (4) spam-rule exemptions for gray (government) verified accounts. The reply "boost" X advertises for Premium is not in this repo (SECONDARY).

### Inferences
- INFERENCE: **Buying Premium does not buy a For You ranking multiplier in this code.** Any Premium effect on an original post's Home reach would be indirect:
  - (a) Credibility mass: Premium accounts are teleport seeds, so they, and accounts they follow or like, gain PageRank mass. High enough cred exempts an account from several spam downranks and drops. For a 36-follower account the score is likely far below any "high PageRank" threshold. The score is logarithmic in mass, and mass is normalised over all users.
  - (b) The embedding text includes "Verified: Blue". That can shift the post's multimodal embedding, which feeds DPP diversity and possibly models that use v8.2 embeddings. This is a learned effect, not a rule. The code does not show which embedding version DPP uses.
  - (c) The advertised reply boost, which lives in conversation ranking outside this repo.
- INFERENCE: The **viewer's** Premium status changes nothing in For You candidate selection or scoring here. It matters only for ads logging and stats, and for whether the viewer can reply under a verified-only conversation control. Whether Premium+ viewers get fewer ads, and so more organic slots, is not shown.
- INFERENCE: Gray (government) verification, not blue, is the verification type that exempts an account from spam rules.

## Key Question 3: Ranking. Engagement weights, negative signals, author diversity, recency, media, links, threads

### Takeaway
For You ranking works in five stages:
1. Phoenix predicts about 25 action probabilities per post.
2. A weighted sum turns them into one score (default weights: copy-link share 20, reply 5, quote 5, DM share 5, follow author 4, share 2, repost 1, like 0.5, click 0.4, open link 0.2, dwell 0.05; profile click 0 and video quality view 0; report −234, mute −58.8, not interested −43.2, block −31.2).
3. The one cold-start lift is applied.
4. The VM ranker multiplies out-of-network posts, and in-network replies and reposts, by 0.75, and scales repeated authors by 1.0 → 0.625 → 0.4375 → … floor 0.25.
5. A DPP diversity pass keeps a top-k from the best 150 and sets every other post's score to 0.

Only the best-scoring post per conversation survives, and candidates older than 48 h are dropped. The +15 "bidirectional" boost is on the weight for P(viewer replies) to an original post whose author the viewer mutually follows.

## Key Question 4: How are impressions counted or logged? Any visibility thresholds?

### Takeaway
The code does not define what counts as an impression. There is no on-screen percentage or time threshold anywhere in home-mixer or Thunder. Home view counts (`view_count_on_home`) come from an external engagement-counts service, and "seen" posts come from client-sent `seen_ids` and impression bloom filters. These counts drive the cold-start eligibility check (fewer than 1,000 home views), the seen-post filters, and an experiment-only like-rate sampler.

### Cited Findings
- `view_count_on_home` is hydrated by `EngagementCountsHydrator` from an external client. The computation is not in the repo — [engagement_counts_hydrator.rs L24-36](https://github.com/xai-org/x-algorithm/blob/44d37ebf87f2185b949cd37b710d410c2a77d21f/home-mixer/candidate_hydrators/engagement_counts_hydrator.rs#L24-L36).
- Cold start requires `view_count_on_home` to be present and below 1,000.
